# v3.3 记账真值校准 + 运维闭环(probe 登录冒烟 / 死人开关 / T7 备份先行 / LLM 诊断口)

> 独立评审升级建议的三件套全部落地。基线 = v3.2.1(ef853f6)。

## 1. LLM 记账真值优先(v3.2 T2 的收尾)

- **实测依据**:GLM `/chat/completions` 流式支持 `stream_options: { include_usage: true }`
  (glm-4-flash 实测 HTTP 200,usage 块随最后一个 chunk 到达,`prompt_tokens/completion_tokens`
  字段齐全;非流式响应恒带 usage)。
- **streamChat**:请求带 `include_usage`;记账收口移到 finally——真值
  (prompt+completion)优先,缺失(上游未返/早期失败)时估算兜底 = 输入(字符/2)
  + 已流出输出(字符/2)。usage 块 choices 为空数组,解析必须先于 choice 判空
  (首个实现坑,已踩已修)。闭包内赋值用 holder 对象,绕开 TS 流分析盲区。
- **chatComplete**(battle/lore 消费):同样真值优先、估算兜底。
- **意义**:字符/2 的方向性偏差(CJK 低记 ≤2 倍)、tools schema 未计入等问题
  全部消失——预算从"量级护栏"升级为"准账本",`pokemon.llm.tokens` 有计费级
  可信度。mock 管线无 usage,估算口径不变(E 段断言不受影响)。

## 2. probe.yml 增强

- **第 4 检查·登录冒烟**:POST /api/auth/login(PROBE_USER/PROBE_PASS secrets)
  断言 200 且 Set-Cookie 为 `__Host-dex_session=`——用户主路径进监控,同时把
  v3.2 唯一挂着的"T6 线上 Set-Cookie 确认"变成每 30 分钟一次的常驻验证。
  secrets 未配置时标记 skipped,不计入失败(与 CI 的无密钥哲学同款)。
- **死人开关**:每次运行 ping `HC_PING_URL`(healthchecks.io 类:成功 ping 本体、
  失败 ping `/fail`,外部服务按超时告警)。覆盖"拨测自身停转"的盲区——GitHub
  会在仓库 60 天不活跃后自动禁用 scheduled workflow,禁用本身无任何信号。
- **Evaluate**:failed_checks 计入登录(非 skipped 时);恢复评论措辞同步。

## 3. backup.yml(T7 先行落地,激活等用户配 secret)

- 每日 cron(05:30 北京时间,生产低峰):`pg_dump --format=custom` →
  `openssl enc -aes-256-cbc -pbkdf2 -iter 200000` 加密 → artifact 保留 30 天,
  sha256 随行;备份不落任何公网可达位置(artifact 仅仓库授权可见且内容加密)。
- **恢复演练每次备份后立即执行**(偏离路线图的"每周 Neon 临时分支"方案,
  理由:更频繁、零成本、保真度相同):解密 → `pg_restore` 进全新 postgres:16
  容器 → users/cards/wallet_tx/battles 行数校验 → 输出恢复耗时。备份不可恢复
  的暴露窗口从一周缩到一天。
- 失败开/追 `backup-alert` issue(与 probe-alert 同款去重)。
- **激活清单**(repo Settings → Secrets):`PROD_DATABASE_URL`、
  `BACKUP_PASSPHRASE`。两个 secret 任一缺失 → 任务 notice 跳过,不报红。

  24h 按消费点(chat/battle/lore)聚合 + top-10 预算桶(ident/feature/tokens/calls)。
