# v2.4 可观测性:自建 RUM + 满意度反馈 + KPI 看板

> 目标(用户 2026-10-17):"加一些可观测性的监测,最好还有一些能体现用户的满意度和一些重要指标的监测"。
> 选型:**自建**(一张事件宽表 + 两个端点)而非 Sentry/PostHog 类 SaaS——零第三方账号、零数据出站,采样、限流、聚合 SQL 每一环都可控可讲;且本站需要的四类信号(web-vitals / JS 错误 / 行为埋点 / CSAT)一张宽表完全承载。

## 六类信号与采集点

| type | 载体 | 触发点 |
|:--|:--|:--|
| `webvital` | web-vitals v6(LCP/INP/CLS/FCP/TTFB + rating) | 动态 import,**独立异步 chunk 3.6KB gzip 不进首包** |
| `jserror` | window error + unhandledrejection | 每会话 ≤10 条 + 同签名 10s 去重(防持续性异常打爆自身管线) |
| `pageview` | hash 路由切换 | 全站 |
| `usage` | pull_single / pull_ten / battle_win / battle_lose / chat_send / wiki_view / login / register | 各业务成功路径一行埋点 |
| `api` | 服务端 `res.on("finish")` 计时 | 按**路由模板**归组(`/api/wiki/:name`,参数不炸维度);`/api/telemetry` 自身不计(采样驱动的合成流量) |
| `feedback`(CSAT) | FeedbackPrompt 组件 | 首页 / 开包成功后 / 战斗结算三个场景,每场景每天最多出现一次 |

客户端管线:20 事件队列 + 10s 批量 flush + pagehide/visibilitychange 走 `sendBeacon`;背压丢最旧保内存上限;一切失败静默——**观测永不影响业务**。

## 服务端三端点

- `POST /api/telemetry`:1-25 events 白名单校验、长度截断、脏 anonId **消毒降级而非拒收**(ingest 端点对元数据宽容、对载荷严格);IP 限流 90/15min;多行单语句 INSERT;5% 采样触发 45 天保留期清理(表不无界增长)。
- `POST /api/feedback`:CSAT 1-5 + 选填 200 字评语。**20h 窗口 upsert**——同身份同场景改口覆盖不刷屏,跨窗口保留历史(满意度趋势是看板核心曲线);不做硬唯一是刻意的:那边 friend_requests 状态机必须唯一,这边趋势要保留,两种正当选型。IP 限流 10/15min。
- `GET /api/metrics/overview`:`requireAdmin` 守卫;10 组聚合并行;**按 Asia/Shanghai 切天**(QA-037 UTC 时区教训);日期列 `to_char` 直出字符串(node-postgres 会把 DATE 解析成带时区的 Date 对象)。

## 数据看板 `#/metrics`(仅管理员)

8 张 KPI 卡(PV / DAU / API 请求+p95 / 错误率 / 新增注册 / JS 错误 / Crash-free 会话 / CSAT)+ 每日流量与功能使用条形图 + Web Vitals p75 表(Google 判级口径)+ API 端点 Top + JS 错误 Top + 满意度分布与评语流。图表是**手写 CSS 条形图,零图表库**——不为管理员低频页面背 70KB 的 Chart.js。入口仅对 `is_admin` 可见,后端 403 兜底。

权限:`users.is_admin` 布尔列,迁移段幂等回填生产测试号 123456;新库冷启动即生效。

## 已知取舍(诚实记录)

- **API 计时 fast path 不 await**:serverless 在响应后冻结会丢少量样本,采集允许有损;5xx 与本地环境全量落库。
- **Crash-free 会话是近似口径**:只统计上报过事件的会话(从未上报的会话本就不可见),看板口径注释标明。
- **feedback 并发双击最坏多一行**:IP 限流兜底,不为旁路数据上事务锁。
