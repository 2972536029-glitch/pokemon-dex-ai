# v3.2.1 独立评审修复批(QA-041~046 全销)

> 依据:独立评审窗口对 v3.2/54878d2 的委托书复审(2026-10-18,见 `qa/findings.md`
> "独立评审"节)。六条发现零豁免全部落地,无 P0。

## 改动清单

- **QA-041(P1)前端 unused-var 挡板**:`eslint.config.js` 前端块加
  `no-unused-vars: error`。关键配套:eslint 核心规则**不认识 JSX 用法**,
  直加会把 `App.jsx` 的 `HomeView`/`Shell` 这类只在 JSX 里使用的组件全部误报
  (首跑 39 error,其中 36 假阳)——必须配 `eslint-plugin-react` 的
  `jsx-uses-vars`(新增 devDep,纯构建链)。配好后从 39 → 3 处真死代码:
  - `Splash.jsx` 删未使用的 `useEffect` 导入;
  - `CollectionView.jsx` `setSortBy` 无人调用 → `const [sortBy]` 收窄;
  - `BattleView.jsx` `stageImpact` 只写不读 → 空位解构 `const [, setStageImpact]`
    (setter 是回放动画的触发器,必须保留)。
  金丝雀复测:.jsx 塞 unused var → exit 1(此前 exit 0)。
- **QA-042 lore.ts meter 一处构造**:gate 与 `chatComplete` 收同一个
  `LlmMeter` 对象,兑现"同桶一处构造"纪律;顺带把 v3.2 插入块的缩进归位。
- **QA-043 删 `pickAiTeam`**:routes-battle 自 v3 起不再调用,全仓零引用的
  导出死代码,删除(server/src/battle.ts)。
- **QA-044 chat 输出上限**:`streamChat` 的 body 增加
  `max_tokens: opts.maxTokens ?? 1024`(`StreamChatOptions.maxTokens`)。
  token 预算是事后计量,输出是最难预估的一头;battle 160 / lore 300 都有界,
  chat 此前裸奔。1024 对回答与 tool_calls 实参都是充裕上界,mock 管线不受影响。
- **QA-045 telemetry E 段防呆**:E 段整体包进 `/api/health` 的 mock 标志检查
  (`health.mock !== true` → 打印 SKIP 说明并整段跳过)。E1 的 14×4000 大请求
  在真实 key 服务器上是 ~28k token 的真金外呼,启动约定(MOCK_LLM=1)不能当
  保险,脚本自己挡在钱前面。CI/本地 mock 服务器行为不变。
- **QA-046 战斗经济补断言**(battle-unit 11 → 13 块):
  - "KO 自动换人不给动量":顶替上场只吃回合回能(+5),不拿 SWITCH_IN(+10)
    ——与主动换人的经济分界此前无断言,有人"顺手补个 +10"测试不红;
    用 energy=7 的非默认初值让误发动量(→22)与回能(→12)一测即穿。
  - "heavy/ult 实付扣费":重招 45、极招 90 的回合内实际扣费此前只有派生表
    断言;补"回能→扣费"结算序的字面量断言(45→15、80→5,AI 持续防御保持
    算术干净)。
