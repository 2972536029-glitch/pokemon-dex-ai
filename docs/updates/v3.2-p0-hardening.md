## T1 Lint 与 CI 挡板 + 包体预算

- **eslint 9 flat config**(`eslint.config.js`):服务端/DB 脚本 `.ts` 全量 typescript-eslint
  recommended(非 type-checked——类型安全已由 `tsc --noEmit` 把关,lint 不重复编译器的活;
  `no-explicit-any` 关闭是仓内既定边界取舍);前端 `.jsx` 挂 react-hooks 规则集——
  rules-of-hooks 是 error(违反即真 bug),exhaustive-deps 是 warn(存量 10 处警告非阻塞,
  挡板只拦 error 级,避免为过挡板大改 hooks)。`qa/` 不进 lint 范围。
- **CI 新步骤**:Lint(error 级挡板)→ Typecheck → Build → **Size budget** → 六套件。
- **包体预算**(`qa/size-check.mjs` + `qa/size-baseline.json`):任一 `dist/assets` 产物
  超基线 +10% 红、基线产物消失红、新产物 >50KB 红、总量超 +10% 红;
  有意变更用 `node qa/size-check.mjs --update` 立新基线。当前基线:17 产物,686,877B。
- 存量清理(为过 error 挡板的最小改动):7 处未使用导入/变量删除、2 处 `let→const`。

## T2 LLM token 预算与熔断

- **集中计量在 llm.ts**:`token ≈ 字符数/2`(GLM 中文≈1字/token、英文≈4字符/token,
  混合语料 /2 是量级正确的工程近似——预算要的是量级护栏,不是计费账单)。
  `streamChat`/`streamChatMock`/`chatComplete` 全部记账:输入流开始入账,输出在
  finally 入账(客户端中断、上游报错同样烧钱,按已流出部分入账)。
  **mock 也计量**:CI 里预算闸降级路径全靠 mock 流触发,mock 不入账 = 测试与生产行为脱钩。
- **双桶预算**(`llm_usage` 表,ident=`u:<id>`/`ip:<ip>`,一个查询同时算两桶):
  - 每用户日上限 `LLM_USER_DAILY_TOKENS`(默认 100k;CI/QA 设 20k 供触发);
  - 全局日预算 `LLM_GLOBAL_DAILY_TOKENS`(默认 2M)。不随 RATE_LIMIT_SCALE 放大
    (token 不是"尝试次数")。DB 故障 fail-open(与 ratelimit 同款取舍:预算保护成本,不是核心)。
- **三消费点全部接闸,熔断是降级不是错误**:
  - chat:超限 → 走 mock 管线照常回答,SSE 先发 `notice` 事件说明原因(前端 useChat
    渲染在回答开头,用户看得见为什么换引擎);
  - battle reasoned:超限 → 规则策略兜底,意图 reason 行照写("今日 AI 预算已用完,
    本轮使用规则策略")——开局/回合后两处收敛为 `reasonedIntentWithBudget` 单入口;
  - lore:超限 → 降级为官方图鉴原文,响应带 `degraded:true`,**降级结果不进缓存**
    (预算明天恢复,缓存会把降级文案钉死成永久答案)。
- **指标**:`/api/metrics/flush` 聚合新增 `pokemon.llm.tokens{feature:chat|battle|lore}` 与
  `pokemon.llm.capped{feature}`(feature 进 tag 不进指标名,Datadog 一张图分组)。
- **QA**:telemetry 套件新增 E0-E9 十断言(见下"验证"),CI 增加 `CRON_SECRET`
  让 CI 也能直调 flush 验证聚合(此前 D3+ 段在 CI 里整段 SKIP)。

## T6 `__Host-` cookie 前缀

- 生产(NODE_ENV=production 或 HTTPS_ONLY=1)会话 cookie 改名 `__Host-dex_session`
  ——浏览器硬校验 Secure + Path=/ + 无 Domain,子域无法再向主域投递会话 cookie;
  本地 http 不满足前缀条件,按环境切回旧名(QA 的 cookie jar 解析无需改动)。
- **不兼容读旧名**:旧 `dex_session` 没有 `__Host-` 保护,接受它等于给子域投递留后门。
  上线后所有旧会话失效一次,重登即恢复(路线图明示可接受)。
- 防御细节:即使调用方环境判定出错,`__Host-` 名字下也强制带 Secure——宁可 cookie
  被浏览器拒收,也不发出一个不符合前缀契约的名字。

## 过程抓到的坑(自审/自测拦截,未进提交)

1. **降档单测首版必然不触发**:AI 迅招先手打出的痛感 +10 恰好把用户能量补到
   25 = strike 费用,降档分支根本不进——同优先级场景里"谁先手"直接改变能量算术。
   修法:AI 改慢速后手。教训:写能量链断言要按引擎的事件顺序逐项排,不能按直觉合并。
2. **减半单测的 RNG 对齐**:同速同优先级时引擎掷先手币,掷币本身消耗随机数,
   两条场景的伤害随机数序号错开一位,ceil 对不齐。修法:攻击方设极速(走速度分支
   不掷币)+ 免疫招不消耗随机数(电/地/飞行单向免疫组合;首选的 ghost/normal 是
   **互免**,双方伤害都是 0,首版又错了一道)。
3. **probe.yml 首版把"落盘本轮结果"放在"评估"之后**:评估读到的是上一轮文件。
   改为直接消费 step outputs,文件只存连续失败计数。
4. **telemetry E 段首版全局熔断验证用错用户**:用了已超个人桶的 U2,降级可能只是
   个人桶触发的,证明不了全局桶——换成个人桶干净的新用户,清理后同一用户恢复,
   才是"全局熔断"的干净证据。
5. **记录给未来**:预算闸与记账必须同桶(chat 的 ident 在 app.ts 一处决定,传给
   gate 与 meter 同一个对象)——分桶错位的表现是"预算永远不满",极难从日志发现。
