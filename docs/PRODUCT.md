## 一、产品概述

**一句话**:一只会查资料、会核对数据、能陪你聊宝可梦的智能图鉴,正在成长为"AI 驱动的宝可梦卡牌平台"。

**解决什么问题**:传统图鉴只能"查"——用户翻表格;本项目让图鉴"对话"和"思考":用户用自然语言提问,产品实时调用真实数据源(PokeAPI)获取答案,并且**机械核对 AI 说的每一个数字**,把大模型最常见的缺陷(幻觉)变成可见、可控、可纠正的工程问题。

**目标用户**:宝可梦爱好者、AI 应用体验者;后续扩展为集图鉴、收藏、对战于一体的轻度玩家。

**当前版本**:v1.1(Phase 1 代码完成并通过两轮 QA,生产部署见 §7)。

## 二、功能全景

### 2.1 AI 问答助手(核心,v1.0 已上线)

- 自然语言提问:{"妙蛙种子有多重?"、"水系怕什么属性?"、"伊布有几种进化?"}
- **Function Calling 实时查证**:模型自主决定调用哪个工具,查到真实数据后才回答;中文译名自动转换为英文名
- **流式输出**:回答逐字呈现;工具调用过程在界面实时可视化(查了什么、成败如何),拒绝黑盒
- **幻觉校验器(产品差异化)**:每条回答的数值断言(种族值/身高/体重)与类型克制断言("A 克 B"两个方向)逐一对照工具返回的事实表;不符自动纠错一次,仍不符则向用户展示"⚠️ 数据存疑"警示。校验原则:宁漏判不误判
- **分层兜底**:查询 404 回喂模型重试、模型限流/断流人话提示、随时停止、僵尸气泡防护

### 2.2 账号与资产系统(v1.1 新增)

- 注册/登录/退出:scrypt 加盐密码、httpOnly Session Cookie、登录限流、防用户枚举
- **钱包**:注册赠 300 图鉴币,每日登录 +50;每一笔增减都有流水可查
- **卡牌收藏**:抽到的卡永久归属账号,收藏页按强度排序展示(官方中文名 + 稀有度徽章)

### 2.3 卡包商店(v1.1 新增)

- 三个卡包:基础包(50 币)/ 进阶包(120 币)/ 传说包(250 币)
- **概率公示**:每个包的稀有度掉率直接展示在购买页(基础包 UR 2% 等),不做暗箱
- **抽卡即订单**:扣币 → 开包 → 入库在同一事务完成;同一订单重试返回同一张卡,绝不重复扣费

### 2.4 AI 推荐顾问(v1.1 新增)

- **组队推荐**:AI 读取你的真实收藏,基于种族值与属性搭配组队;**只推荐你拥有的卡**——推荐越权会被守卫检出、自动纠错、仍不改则向用户明示
- **卡包购买建议**:基于收藏缺口 + 钱包余额 + 卡包概率给出依据明确的建议,**允许并鼓励 AI 说"这个包你不缺,不建议买"**

## 三、产品架构

```
浏览器 (React 19 · Vite)          服务端 (Node 24 · Express 5 · TypeScript)        外部
┌──────────────────┐   POST /api/chat    ┌────────────────────┐   tools   ┌─────────┐
│ 图鉴 / 商店 /     │◀────SSE 事件流──────│ Agent 循环(自研)    │──────────▶│ PokeAPI │
│ 收藏 / 登录       │   delta/tool/done   │  工具调用 → 观察 →   │           └─────────┘
└──────────────────┘                     │  再规划(≤6 轮)      │   chat    ┌─────────┐
┌──────────────────┐                     │  ↓ 事实表           │──────────▶│ GLM-4   │
│ Postgres(资产)  │◀────用户状态工具────│ guard 幻觉校验      │           └─────────┘
│ 用户/钱包/收藏/订单│                    └────────────────────┘
└──────────────────┘
```

| 层 | 技术 | 关键决策 |
|---|---|---|
| 前端 | React 19 · Vite · JavaScript | 手写 SSE 解析(EventSource 不支持 POST);hash 路由零依赖 |
| 服务端 | Node 24 · Express 5 · TypeScript | **自研 Agent 循环**(约 700 行,每步可解释可调试) |
| 数据 | PostgreSQL · pg 驱动 | 本地 Docker / 生产 Neon 同一套 SQL;仓储层隔离 |
| 模型 | GLM-4-Flash(智谱,免费) | OpenAI 兼容接口,模型可配置 |
| 部署 | Vercel(前端 + API)/ Docker | 单容器亦可独立运行;密钥仅存服务端 |

**安全红线**:模型凭证只在服务端;用户身份由会话在服务端解析后注入 AI 工具,模型永远无法传用户 ID(工具层防越权);密码 scrypt 加盐;登录限流;错误信息不区分"用户不存在/密码错误"。

## 四、质量保障

**测试金字塔**(报告全文见 docs/qa-report-phase1.md,台账 qa/findings.md):

- **接口级**:18 项断言的自动化 E2E 套件(qa/e2e.mjs),覆盖注册/会话/钱包/抽卡幂等/余额不足/跨用户隔离/失败话术,**连跑两遍 18/18 全过**
- **代码级**:独立 QA 两轮评审(第一轮发现 1 P1 + 12 P2,全部修复;第二轮复核 13/13 销项,回归无新问题),最终结论 **「Phase 1 通过」**
- **UI 级**:浏览器全流程实测(注册 → 抽卡 → 收藏 → AI 顾问),关键路径截图存档
- **守卫实测**:真实模型测试中,守卫成功拦截"推荐用户未拥有的卡"并强制纠正——幻觉校验从口号变成了可演示的行为

**明确的边界(诚实声明)**:幻觉校验覆盖数值与类型克制断言及推荐所有权,开放语义断言不核对;登录限流为单实例内存版(多实例需共享存储);免费模型在开放组队题上推理较弱(可配置升级)。

## 七、部署与运行状态

- **线上环境**:Vercel(https://pokemon-dex-ai.vercel.app),GLM-4-Flash 真实模型模式
- **生产数据库**:Neon Postgres 接入中——接入前,v1.1 的账号/卡包功能在线上返回友好提示(图鉴与 AI 问答不受影响);接入后数据即永久持久
- **本地运行**:`docker compose up -d`(数据库)→ `npm run seed`(目录)→ `npm run dev:ai` + `npm run dev`;无模型 key 自动进入演示模式(工具层仍走真实 API)
- **容器化**:`docker build` + `docker run -e GLM_API_KEY=xxx`,单进程单端口
